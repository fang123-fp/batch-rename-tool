# 批量文件重命名台

这是一个支持两种运行方式的本地工具：

- 静态模式：直接打开 `index.html`，适合普通文本文件和轻量使用
- 本地后端模式：启动 `node server.js` 后访问页面，PDF 会优先交给服务端统一识别，适合扫描证书、老浏览器、局域网多人共用

当前推荐你在真实业务里使用“本地后端模式”。

## 为什么加本地后端

之前所有 PDF 解析和 OCR 都在访问者自己的浏览器里执行，会受到这些因素影响：

- 用户浏览器版本差异
- Win7 / 老版 Chrome 的兼容性问题
- 多次“从内容重新读取”时的状态串扰
- 批量扫描 PDF 在弱机器上的不稳定表现

现在改成：

- 页面仍然负责上传、字段编辑、重命名下载
- PDF 识别优先交给启动服务的那台电脑统一完成
- 前端浏览器只负责显示结果，不再承担核心 OCR 稳定性

这能显著减少“这一份识别到了，下一份又漏字段”这类问题。

## 功能

- 一次选择多个文件
- 自定义字段，例如 `证书编号`、`客户名称`、`管理编号`
- 点击 `批量替换名称` 后再统一从文件内容中读取字段值
- PDF 证书第一页锁定提取
- 支持扫描版 PDF OCR
- 用模板控制文件名，例如 `{证书编号}-{客户名称}`
- 自动保留原始后缀
- 自动处理重名结果
- 导出重命名后的 ZIP
- 导出诊断信息继续排查

## 推荐用法：本地后端模式

### 环境要求

- Node.js 18+
- 桌面版 Chrome / Edge 其中之一
- 首次启动需要执行一次 `npm install`

### 安装依赖

```bash
npm install
```

### 启动服务

```bash
npm start
```

或直接双击：

- macOS：`start_lan_server.command`
- Windows：`start_lan_server.bat`

启动后会显示：

- 本机访问地址，例如 `http://localhost:8123`
- 局域网访问地址，例如 `http://192.168.x.x:8123`

### 这种模式下谁在做识别

- 启动服务的那台电脑：真正执行 PDF 解析和 OCR
- 其他访问页面的电脑：只上传文件、查看结果、下载 ZIP

所以如果你把它部署到另一台电脑，本质上就是“那台电脑作为统一识别节点”。

## 静态模式

如果只是临时使用，也可以：

- 直接双击 `index.html`
- 或用任意静态服务器打开

但要注意：

- 这种模式下没有 `/api/extract` 本地后端
- PDF 会退回到访问者自己的浏览器里识别
- 稳定性不如本地后端模式

## 使用步骤

1. 上传文件
2. 配置字段
3. 设置命名模板
4. 点击 `批量替换名称`
5. 检查自动读取结果，必要时手动修正字段
6. 点击 `下载重命名 ZIP`

## 当前识别策略

- `txt`、`csv`、`tsv`、`json`、`md`、`html`、`xml`、`docx`：前端直接读取
- `pdf`：
  - 如果页面连接到了本地后端，优先走后端统一识别
  - 如果本地后端不可用，再回退到前端本地识别
- 当前证书样本默认只读取第一页

## 常见问题

### 1. 为什么 GitHub Pages 不能解决这个问题

GitHub Pages 只能托管静态文件，不能运行 `node server.js`，所以不能提供这次新增的本地后端识别能力。

### 2. 如果服务提示没找到浏览器怎么办

可以先安装 Chrome，或设置环境变量：

```bash
PUPPETEER_EXECUTABLE_PATH=/你的浏览器可执行文件路径
```

### 3. 手动改过的字段会不会被重新读取覆盖

不会。

现在重新读取时只会覆盖：

- 原本为空的值
- 或者仍然等于上一次自动识别结果的值

如果你手动改过，工具会保留你的人工修正。

## 说明

- 这个工具不会直接修改原始文件
- 下载结果是一个新的 ZIP 包
- ZIP 里包含 `rename-manifest.json`
- 首次 OCR 依赖加载仍然会稍慢，但后续会复用
